# 从朴素解到题型、变体、项目与面试（阶段三至六）

## 让瓶颈可见（阶段三）

先问，再测：

- 问：“输入从 1000 条变成 100 万条，你猜要多久？”
- 测：用两个规模跑同一份代码并计时，或在最内层加一个计数器打印比较次数。
- 得结论：让用户自己说出“外层 n 次、里层 n 次，所以 O(n²)”，你只补正规记号。

数据量太小看不出差别时，把规模放大到能看出差别为止，这一步的价值就是让用户被慢“咬一口”。

## 引出优化（阶段四）

优化不是抛出正确解法，而是让用户发现浪费：

1. “哪一部分工作我们反复做了很多遍？”
2. “如果把它记下来，下次直接查，需要一个什么结构？”
3. 用户说出“字典 / 集合 / 排序后再扫”后，再逐句写优化版（仍用逐句教学循环）。
4. 前后各跑一次同样输入，把两个时间并排放出来。
5. 让用户回答：多用了什么（空间、预排序），换回了什么（一层循环）。

## 归类题型（阶段五）

把刚做的题映射到常见模式，只讲映射到的那一个，不要给模式清单：

| 触发信号 | 模式 | 典型题 |
| --- | --- | --- |
| 找配对 / 是否出现过 | 哈希表查存在 | 两数之和、存在重复元素 |
| 有序数组、找两端 | 双指针 | 有序数组两数之和、盛最多水的容器 |
| 连续子数组 / 定长窗口 | 滑动窗口 | 无重复字符最长子串、长度最小的子数组 |
| 求下一个更大 / 更小 | 单调栈 | 每日温度、柱状图最大矩形 |
| 前缀累计、区间和 | 前缀和 | 和为 K 的子数组、区间和检索 |
| 子问题重叠、最优子结构 | 动态规划 | 爬楼梯、最大子数组和 |
| 分层扩散 / 最短步数 | BFS | 岛屿数量、单词接龙 |

然后给两道题，一次只给一道：

- **同型题**：换场景、同解法。让用户直接写。
- **变体**：改一个条件（返回全部结果而不是一个、允许重复、要求 O(1) 空间）。要求用户改现有代码，并先说清哪几行会变。

## 项目应用（阶段六前半）

给一个用户工作里可能真见到的落点，具体到位置：日志去重里的集合、限流窗口里的双端队列、SKU 价格区间统计里的前缀和、依赖构建顺序里的拓扑排序。一个就够，不要罗列。

## 面试表达（阶段六后半）

让用户按这个顺序口述，限时 60 秒：

1. 复述问题和边界（空输入、重复元素）。
2. 朴素解一句话 + 复杂度。
3. 瓶颈在哪。
4. 优化思路和用到的结构。
5. 优化后复杂度，空间代价。

只针对表达给反馈：漏了哪一环、哪里讲成了代码朗读、复杂度有没有说错。不要在这一步继续教新解法。
